# KalshiPaperSim

A **paper-trading competition platform for Kalshi prediction markets**, built on real captured
Kalshi data: real markets, real quotes, real order-book depth, real candlesticks, the real
quadratic fee formula, and the real reciprocal YES/NO pricing rule. Twelve aggressive algorithmic
strategies with unique usernames compete over a one-year calendar; every result is **computed by a
deterministic replay engine** and every input is traceable to an official source. Two of them
(`LongshotFader_FLB`, `PanicDip_ShockTiming`) were recreated this session from public trading
write-ups — see [Strategy sources](#strategy-sources).

## The honesty contract

This repository was rebuilt after an audit found that its predecessor **invented data**. The rules
below are enforced by code and by tests, not by intention.

| Rule | How it is enforced |
| --- | --- |
| No price, quote, fee, market or series is invented | Every value lives in `src/verified-snapshot.js` / `src/verified-candles.js` with the URL it was captured from |
| No performance number is hard-coded | `validateStrategies()` rejects any strategy carrying a literal result; strategies expose executable `decide(ctx)` code only |
| An oversized order is never filled at a made-up price | `exhaustionPolicy: 'partial'` fills only depth that exists and reports the remainder as **unfilled** |
| Modelled data is labelled as modelled | `depthModel` / `source` on every book; the pill in the UI says REAL SNAPSHOT or SIMULATED |
| A strategy that never traded is not ranked | `LEADERBOARD_QUALIFICATION.minTrades = 1`; it is listed as *unranked* with the reason |
| Attribution must add up | `equityChange = realizedPnl + unrealizedPnl − feesPaid`, asserted per strategy (residual < $0.01) |
| Deep comparisons must be deep | `stableStringify()` — `JSON.stringify(v, keyArray)` filters nested objects and silently skipped every price field (Irregularity #20) |
| Anything odd found in official data is flagged, not smoothed over | 25 entries in [IRREGULARITIES.md](IRREGULARITIES.md) |

What is **real**: market objects, series fee configs, order-book levels, **136 captured daily
candlesticks** (two full 61-bar windows on the two Nasdaq-100 strikes plus a 14-bar KXBTCY window),
exchange status, the historical cutoff, the fee formula and its published table.

What is **modelled** (and labelled): depth *behind* the quoted touch during a replay (Kalshi's
candlesticks carry no depth), the market-maker feed that moves prices when no API credentials are
configured, and the one-year calendar clock.

## Run it

### Server mode (full features)

```bash
npm start                 # http://localhost:3000  (binds 0.0.0.0)
```

Nothing to install beyond Node 18+ — there are no dependencies. Optional environment variables:

| Variable | Default | Effect |
| --- | --- | --- |
| `PORT` | `3000` | HTTP port |
| `HOST` | `0.0.0.0` | Bind address |
| `KALSHI_API_KEY_ID` / `KALSHI_API_PRIVATE_KEY` | unset | Enables the **authenticated WebSocket relay**, so the feed carries real Kalshi ticks instead of modelled ones |
| `ALLOW_USER_CODE` | `false` | Server-side execution of user-submitted Strategy Lab code. Off by default; the Lab runs client-side either way |

### Static mode (GitHub Pages)

`npm run build` copies `index.html` and `src/` into `docs/`. Opening `docs/index.html` — or the
Pages URL — runs the whole app in the browser: it detects that no server is present, imports the
same modules directly, computes the competition locally and stores your year in `localStorage`.
Every number is identical to server mode because it is the same code.

## Fee engine

Kalshi's published formula, implemented exactly and checked against Kalshi's own table:

```
taker: fees = round up(M × 0.07   × C × P × (1 − P))
maker: fees = round up(M × 0.0175 × C × P × (1 − P))
round up = "rounds up such that the fee + positionCost is rounded to a centicent"
```

Two verified facts drive the results:

- **`KXBTCY` has `fee_multiplier: 0`** — the BTC series is genuinely fee-free. Confirmed twice:
  the live `GET /series/KXBTCY` capture *and* the PDF's Non-Standard Fees table.
- **Fees are asymmetric by side.** Buying YES at $0.12 costs ≈ 6.2% of the premium in fees; buying
  NO at $0.88 costs ≈ 0.8%. That single asymmetry decides which strategies survive the window.

Source: <https://kalshi.com/docs/kalshi-fee-schedule.pdf> (effective 2026-07-07).

## Multi-market accounting

The competition now replays **three markets at once** — both tails of the same Nasdaq-100 event
(`KXNASDAQ100Y-…-T33000` and `…-T19000`, 61 real daily bars each) plus the fee-free
`KXBTCY-27JAN0100-T149999.99` (14 bars). `src/market-analytics.js` accounts for that:

- **per-market exposure** — contracts traded, fees, realized P&L, contracts still open, capital at
  risk and each market's share of it;
- **concentration** — a Herfindahl–Hirschman index over capital at risk (1.00 = one market);
- **cross-market correlation** — Pearson ρ of daily close-to-close *dollar* changes on the real
  closes. The two Nasdaq strikes share 61 periods (ρ = +0.15); KXBTCY shares only 14, so its
  correlation is reported as **not computed** with the overlap it does have, rather than a number
  nobody can check.

- **The favorite leg of `LongshotFader_FLB` cannot fire on this universe.** Every captured contract

## Limitations and remaining work

**Limitations of what exists today**

1. **The real window is still only 61 daily periods.** Two markets now have a full 61-bar window
   (2026-07-19 → 2026-09-17) and KXBTCY has 14. Kalshi's live history window is ~3 months, so a
   genuine one-year competition cannot be replayed from public data yet — the 52-week calendar is a
   clock, and the ingest job exists to lengthen the window one day at a time.
2. **Depth behind the touch is modelled.** Candlesticks carry no order book, so replay fills walk a
   ladder anchored on each bar's real bid/ask with modelled size behind it. Real fills would differ.
   The sensitivity sweep shows how much this matters per strategy.
3. **The ingest job has never completed a live run here.** Direct TLS to `*.kalshi.com` is dropped
   from this sandbox (Irregularity #4), so `data/history/` is empty and every result still comes from
   the 2026-09-17 captures. The script, its `--dry-run` URL list and the GitHub Actions workflow are
   in place and reviewable; they have not been exercised against the live API.
4. **No settlement outcome.** None of the captured contracts had resolved (status `active`,
   `result: ""`), so positions are marked to the last real quote. `POST /api/settle` and the
   sensitivity sweep's YES/NO rows are labelled **hypothetical scenarios**.
5. **Point-in-time quotes.** Without API credentials the app never fetches live prices; with
   credentials only the WebSocket relay goes live (browser CORS + signed handshake).
6. **Correlations are window-specific.** ρ is measured over one 61-period window on contracts that
   have not settled. It is a description of that window, not a forecast.
7. **The sandbox is defense-in-depth, not a security boundary.** `lintSource` is a token/pattern scan
   and user code still runs in your own browser (or your own server with `ALLOW_USER_CODE=true`).
8. **Single-process store.** The year lives in one JSON file under `data/store/` (git-ignored). No
   multi-user auth, no locking, no database.

**Suggested next work (in priority order)**

1. **Run the ingest job for real.** Uncomment nothing — just let `.github/workflows/daily-history.yml`
   run for a week, then re-run `node scripts/sensitivity-sweep.mjs` on the longer window. This is the
   only thing that turns the 52-week competition from a clock into a measurement.
2. **Broaden the universe further.** Add `KXINXY` (S&P 500 yearly range — the series object is
   already captured, `fee_multiplier: 1`) and a full-window KXBTCY capture. Both need the same
   `/series/{series}/markets/{ticker}/candlesticks` call the ingest job already makes; only the ticker
   list changes.
3. **Wire the accumulated store into the replay.** `src/history-store.js` already reads it and
   `auditHistoryAgainstRepo()` compares it with the in-repo captures; the next step is to let
   `getReplayableMarkets()` prefer the longer stored series when one exists.
4. **Authenticate the relay and smoke-test it live.** The relay code path exists but has never run
   against the live endpoint (no credentials were available in either session).
5. **Real settlement tracking in production.** `scripts/track-settlements.mjs` is written and unit
   tested; it needs one live poll after these markets resolve (T33000 and T19000 close 2026-12-31,
   KXBTCY closes 2027-01-01) to confirm the `finalized` + `result` path end to end.
6. **Headless browser test.** `test/ui-smoke.mjs` renders against a DOM stub (58 assertions incl. 8
   new ones). A Playwright run would also verify layout, the live WebSocket feed and the Pages build;
   the browser download is not reachable from this sandbox.
7. **Per-market capital allocation.** Cross-market exposure is now *measured*; the next step is to
   compare how the "highest return" mandate behaves with and without per-market caps.
