# KalshiPaperSim

A **paper-trading competition platform for Kalshi prediction markets**, built on real captured
Kalshi data: real markets, real quotes, real order-book depth, real candlesticks, the real
quadratic fee formula, and the real reciprocal YES/NO pricing rule. Forty-one aggressive
algorithmic strategies with unique usernames compete across three flights (daily, hourly, micro);
every result is **computed by a deterministic replay engine** and every input is traceable to an
official source. Roster entries were recreated from public trading write-ups — see
[Strategy sources](#strategy-sources), and the [signal-source ledger](#signal-sources-the-mastersite-review)
for the site-by-site review of the owner's own projects (weather → `KXHIGHNY`, gold → `KXGOLD15M`).

**What is new in this revision (2026-09-19):** three real desk defects found and closed on the fresh
store — the cash cap now pays the **exact** official fee (the old flat 2% reserve let a $500 account
book $520.87 of cost at 9¢), its own binary search can no longer spin forever, and the desk module
**keeps six settled contracts with the exchange's own results** (open contracts had filled the whole
cap, degrading settlement to fixtures). The **FDA half of the point-in-time signal archive** shipped:
the official openFDA Drugs@FDA API captured four times a day, one subject per tracked FDA-approval
market with the query taken from each market's own rule text, and the first strategy on it
(`FDAEdge_DrugsFDA`) is a genuine forward test that abstains until an approval flip overlaps a live
market. Fresh social-media research (R15, r/KalshiBTCUporDown15) produced `HighProb_Scalp8095` — the
75–80¢-entry/95¢-take-profit scalp, recreated mechanically and measured honestly at −65.03%. Previous
revision (2026-09-18): the **Live Desk** — a tenth section that places paper orders on **real,
still-open** Kalshi contracts at a chosen cut-off, priced only from order-book ladders captured from
the official API, with depth-bound fills, the published fee schedule with the series multiplier, real
$1.00/$0.00 settlement and a 13-invariant audit (`node scripts/run-live-desk.mjs`); plus the first
**daily-settling markets** (40 real NYC high-temperature brackets, 8 real 15-minute gold markets) so
the engine books **real $1.00/$0.00 settlements mid-replay**, and the **point-in-time NWS forecast
archive** behind the first forward-tested strategy (`ForecastEdge_Weather`).

## The honesty contract

This repository was rebuilt after an audit found that its predecessor **invented data**. The rules
below are enforced by code and by tests, not by intention.

| Rule | How it is enforced |
| --- | --- |
| No price, quote, fee, market or series is invented | Every value lives in `src/verified-snapshot.js` / `src/verified-candles.js` / `data/history/*.json` with the URL it was captured from |
| No performance number is hard-coded | `validateStrategies()` rejects any strategy carrying a literal result; strategies expose executable `decide(ctx)` code only |
| An oversized order is never filled at a made-up price | `exhaustionPolicy: 'partial'` fills only depth that exists and reports the remainder as **unfilled** |
| No order may fill more than the market actually traded | `maxFillFractionOfPeriodVolume` (default 10%) caps every fill — taker and resting maker — at that share of the bar's real `volume_fp`; the rest is reported, not filled (Irregularity #29) |
| A longer stored series can never rewrite a captured one | `src/history-merge.js` admits a stored series only as a **verified superset** — every shared bar must match field-for-field and the stored one must add a bar |
| Modelled data is labelled as modelled | `depthModel` / `source` on every book; the pill in the UI says REAL SNAPSHOT or SIMULATED |
| A strategy that never traded is not ranked | `LEADERBOARD_QUALIFICATION.minTrades = 1`; it is listed as *unranked* with the reason |
| Attribution must add up | `equityChange = realizedPnl + unrealizedPnl − feesPaid`, asserted per strategy (residual < $0.01) |
| Deep comparisons must be deep | `stableStringify()` — `JSON.stringify(v, keyArray)` filters nested objects and silently skipped every price field (Irregularity #20) |
| Anything odd found in official data is flagged, not smoothed over | 45 entries in [IRREGULARITIES.md](IRREGULARITIES.md) |

What is **real**: market objects, series fee configs, order-book levels, **10,905 captured daily
candlesticks across 53 markets (2025-08-15 → 2026-09-18)**, every bar's traded
volume, exchange status, the historical cutoff, the fee formula and its published table.

What is **modelled** (and labelled): the market-maker feed that moves prices when no API credentials
are configured, and the one-year calendar clock. Depth *behind* the quoted touch is no longer a model
for the tracked universe: `src/captured-depth.js` holds a real ladder captured from
`GET /markets/{ticker}/orderbook` for every one of the 30 markets, and the default run fills against
those ladders re-anchored to each bar's real quoted touch (switch to *Modelled ladder* in the
leaderboard controls to see the comparison — it moves results by up to ~13pp). Fills are *additionally*
bounded by the volume that really traded, and any market without a capture says so per market.

## The Live Desk — placing real trades on open contracts

The competition leaderboard replays **history**. The Live Desk is the separate section that does the
other half of the request: it **places paper orders on real, still-open Kalshi contracts**, at a
chosen instant, and then tracks every one of them with the same evidence standard. It is the
"simulate placing a real trade" surface, and it is deliberately built so that it *cannot* quote a
price the exchange never showed.

**What a desk trade is.**

1. **A point in time.** The desk runs at a cut-off (the newest captured ladder, or −6h / −12h /
   −15h / −24h / −48h / −96h / −240h). Every contract's **own published `close_time`** decides
   whether it was open then — the current `status`/`result` is deliberately not used, so a contract
   that has since been finalized is still tradeable *at an earlier cut-off* if it was open then.
2. **A real ladder, never a model.** An order can only be priced from an order-book ladder that was
   **captured at or before** the cut-off. A ladder captured later is listed but refused
   (`LOOK_AHEAD_LADDER`); that refusal is part of the audit. Buying YES consumes the real **NO**
   bids at `1 − no_bid`, because that is the counterparty the exchange actually has.
3. **Real size.** Fills walk the captured levels in price order; an order larger than the book fills
   what exists and reports the rest as **UNFILLED**. No session may take more than 10% of the
   contract's real liquidity base (the larger of its 24h volume and its open interest, falling back
   to lifetime volume) — the ladder is still the binding constraint in every fill.
4. **A real account, not a fantasy one.** The paper account can neither borrow nor short: a buy is
   re-sized to what its cash can pay for (fee included) and the reduction is recorded as
   `cashCapped`, a sell with no position is refused (`NO_POSITION_TO_SELL`), and a crossed resting
   order is capped the same way at the crossing instant. See Irregularity #49 — the equity identity
   closes just as neatly on a negative cash balance, which is why this needed its own invariant.
5. **Official fees and real settlement.** Fees come from Kalshi's published quadratic schedule with
   the **series multiplier the exchange reports** (`fee_multiplier` / `fee_type` on the captured
   market, including the maker-fee series), and a held position is resolved by the exchange's own
   `result` / `settlement_value_dollars` / `settlement_ts` — $1.00 or $0.00, no settlement fee.

**Why the numbers are trustworthy.** `buildDeskReport()` is one function used by both the server
and the GitHub-Pages build, so the two can never disagree. `node scripts/run-live-desk.mjs` exits
non-zero unless all desk invariants hold; they are run again in the browser and published in the
tab (D1–D13, each with its official source). The desk does **not** transmit anything to Kalshi: it
is a paper simulator, and the disclosure says so on the tab itself.

**What is tracked for every placed trade** (`data/reports/live-desk-ledger.jsonl`, and the same
records behind the tab): the order (strategy, ticker, side, count, type, limit), the fill (price,
touch, slippage in ticks and dollars, the exact captured levels consumed, the liquidity cap that
applied, the official fee with its multiplier), the resting order and its queue position, the
cancellation, the mark, and the settlement with the exchange's result and timestamp. Every record
carries the **ladder URL + capture timestamp** and the **market object URL + capture timestamp** it
came from, so any line can be re-checked against the source by hand.

**The desk entrants** carry unique usernames like the roster, trade only to maximise return (no
stop-losses, no position caps — sizing is a fixed fraction of cash bounded by real depth), and are
ranked on the same $100,000 start. A desk entry that finds no real size at a cut-off is listed as
**no fillable order**, never as 0%. Those usernames are reserved for humans even when the stored
year predates the desk (`DESK_RESERVED_USERNAMES`, kept set-equal to the roster by test 104).

**Where the year keeps it.** Running the desk — `GET /api/live-desk` on the server, or the Live
Desk tab in the static build — calls `attachDeskSession()`. Compact per-entrant results,
explanations, and every FILL/SETTLE row land in the one-year store (`deskMemory` plus `tradeLog`
rows with `kind: 'desk'`). Re-running the same cut-off replaces those rows rather than duplicating
them. Open positions are **not** carried into the next cut-off: that remaining gap is the
multi-day book, not this attach.

## The Desk Season — the same book, carried across real capture rounds

The Live Desk answers *"what would this trade have cost at this instant?"*. It cannot answer the
question a trader actually asks: *"if I had placed that order and then left it on, what happened
next?"* The **Desk Season** is that surface. It is one portfolio per entrant, carried from the first
real capture round to the last, with nothing reset in between.

**What a season is.**

1. **Rounds are real capture instants.** `seasonSchedule()` reads the store's own ladder timestamps,
   groups them into ingest *batches* (a runner that walked 68 tickers in one minute is one look at
   the exchange, not 68 sessions), stamps each round at the last instant of its batch, and keeps the
   batch only if it added at least one ladder the season had not seen. No round time is invented and
   no ladder is re-anchored.
2. **One book.** Cash, open positions, resting orders and the cumulative 10%-of-liquidity cap carry
   from round to round. A position opened in round 2 that settles in round 4 is resolved by the
   exchange's own `result` / `settlement_value_dollars` / `settlement_ts` inside the season — real
   terminal payouts, not marks.
3. **The walk between rounds is real.** Before each decision the season applies the real events in
   the window it just crossed: later captured ladders, later candlestick quotes, and real
   settlements. A resting (maker) order only fills if one of those real quotes crosses it, and the
   fill record names the quote that did (`crossedBy`).
4. **Point-in-time, still.** The decision view per round is built with the same
   `buildDeskUniverse({asOf: round})` the single session uses: a strategy sees only ladders and bars
   captured at or before that round. The forward walk reads the raw store bars, and that asymmetry
   is deliberate — it is what makes a maker fill possible at all (Irregularity #46).

**What is tracked.** The season ledger (`data/reports/desk-season-ledger.jsonl`) carries the order,
the fill (with the exact levels consumed, the slippage in ticks and dollars, the official fee and
its multiplier), the resting order, the canvas of marks at the close, the settlement, and a
`SNAPSHOT` per entrant per round (cash, market value, equity, open contracts) so the equity curve
can be re-derived line by line. Every record keeps the source URL and capture timestamp it came
from.

**The audit.** `auditSeason()` re-runs the 13 single-session invariants (D1–D13) over the whole
season and adds the season's own S1–S12: real capture instants only, strictly increasing rounds, a
fill inside its round priced from a ladder captured at or before it, one book per entrant, an equity
curve that closes to the reported equity, no double settlement, maker fills that name their cross,
per-round event instrumentation, no-fill entrants reported as unranked, an equity curve that is
the same arithmetic as the final number, a cumulative liquidity cap re-derived from the ledger, and
**no borrowing and no shorting** (S12 — no snapshot may show negative cash and no SELL may exceed
what the entrant already held). `node scripts/run-desk-season.mjs` exits non-zero unless
every one of them holds, and the same check set is published on the tab.

**Reproduce it.**

```bash
node scripts/run-desk-season.mjs                      # every real capture round, $100,000 start
node scripts/run-desk-season.mjs --max-rounds=6 --spacing-minutes=0 --batch-minutes=5
node scripts/run-desk-season.mjs --quiet              # exit code only (0 pass, 1 audit mismatch, 2 no schedule)
```

## Fee engine

Kalshi's published formula, implemented exactly and checked against Kalshi's own table:

```
taker: fees = round up(M × 0.07   × C × P × (1 − P))
maker: fees = round up(M × 0.0175 × C × P × (1 − P))
round up = "rounds up such that the fee + positionCost is rounded to a centicent"
```

Two verified facts drive the results:

- **`KXBTCY` has `fee_multiplier: 0`** — the BTC series is genuinely fee-free. Confirmed twice:
  the live `GET /series/KXBTCY` capture *and* the PDF's Non-Standard Fees table.
- **Fees are asymmetric by side.** Buying YES at $0.12 costs ≈ 6.2% of the premium in fees; buying
  NO at $0.88 costs ≈ 0.8%. That single asymmetry decides which strategies survive the window.

Source: <https://kalshi.com/docs/kalshi-fee-schedule.pdf> (effective 2026-07-07).

## Multi-market accounting

The competition replays **30 markets at once** — 20 Nasdaq-100 yearly-range strikes, nine KXBTCY
strikes (the fee-free series) and four S&P 500 yearly-range strikes, 204–268 real daily bars each
(2025-12-24 → 2026-09-17). `src/market-analytics.js` accounts for that:

- **per-market exposure** — contracts traded, fees, realized P&L, contracts still open, capital at
  risk and each market's share of it;
- **concentration** — a Herfindahl–Hirschman index over capital at risk (1.00 = one market);
- **cross-market correlation** — Pearson ρ of daily close-to-close *dollar* changes on the real
  closes, computed only above a minimum overlap. Pairs beneath that floor are reported as
  **not computed** with the overlap they do have, rather than a number nobody can check.

## Limitations and remaining work

**Limitations of what exists today**

1. **The window is 268 periods, not 52 weeks.** Every market is backfilled to its own `open_time`,
   which for these series is 2025-12-23/24 — close to nine months. It is *not* a year, and it never
   will be from candlesticks alone: a market that opened last week cannot have a year of bars. The
   one-year competition calendar is therefore still a clock, and the oldest series in the universe
   sets how much of it can be measured.
2. **Depth behind the touch is captured, but re-anchored — not point-in-time.** The ladder is real
   (captured from the official orderbook endpoint), yet it is a single snapshot per market that is
   *re-anchored* to each bar's real quoted touch. A point-in-time ladder for every period would need
   streaming captures. Fills are also bounded by the bar's real traded volume (Irregularity #29), so
   the remaining exposure is the shape of the book between snapshots, not an invented one.
3. **Real settlements exist for the intraday universe and the settled daily markets.** The 60-minute
   store holds 199 markets of which 173 are finalized with the exchange's own result, and the
   1-minute store 43 of 43 (computed by `src/store-facts.js` on every load — these numbers grow
   with every ingest); their results settle for real ($1.00/$0.00, no fee). The still-active index
   markets of the daily flight remain `status: active, result: ""`, so positions there are marked
   at the last real quote, and `POST /api/settle` plus the sensitivity sweep's YES/NO rows stay
   labelled **hypothetical scenarios**. T33000 and T19000 close 2026-12-31; KXBTCY closes 2027-01-01.
4. **Point-in-time quotes.** Without API credentials the app never fetches live prices; with
   credentials only the WebSocket relay goes live (browser CORS + signed handshake). The relay has
   still never run against the live endpoint — no credentials existed in any session.
5. **Correlations are window-specific.** ρ is measured over one window on contracts that have not
   settled. It is a description of that window, not a forecast.
### The Live Desk — what it cannot do yet

- It prices only contracts with a **captured ladder**: 68 of 287 tracked markets
  on the 2026-09-18 capture (120 open contracts carry real quotes but no ladder
  and are listed as not priceable, each with the ingest command that fixes it).
- Cut-offs older than about −15h price nothing, because no ladder was captured
  before them yet; the scheduled 16:40 UTC books capture adds one per day.
- It attaches **one session per cut-off** into the one-year memory
  (`deskMemory` + `tradeLog` with `kind: 'desk'`). Re-running the same as-of
  replaces those rows. Open positions are carried only inside a **Desk Season**
  (`attachDeskSeason`, `kind: 'desk-season'`), which spans the captured window
  (19.6 h on the 2026-09-18 store, 6 rounds) — not a calendar year. A year-long
  continuous book needs many more scheduled captures; the schedule machinery
  picks each new one up automatically.
- It never transmits an order: a desk fill is a claim about the captured book,
  not about a real account.

6. **2,839 of the 10,905 stored bars (26.0%) are no-trade periods** — no OHLC at all, just the resting
   quotes and `previous_dollars`. On those bars the touch is carried forward, so a "fill" can rest on
   a stale price (Irregularity #30).
7. **The sandbox is defense-in-depth, not a security boundary.** `lintSource` is a token/pattern scan
   and user code still runs in your own browser (or your own server with `ALLOW_USER_CODE=true`).
8. **Single-process store.** The year lives in one JSON file under `data/store/` (git-ignored). No
   multi-user auth, no locking, no database.

### What the per-market capital-allocation experiment found

`scripts/cap-comparison.mjs` replays the roster under no cap, 50%, 25% and 10% of equity per market,
across three seeds (144 runs). With fills bounded by real traded volume, **the caps barely move the
result**: `ContrarianKing_100x` +9.34% uncapped vs +9.24% at a 10% cap, `VolatilityArb_MM` +9.25% vs
+9.82%, `GammaWhale_Squeeze` −14.84% vs −14.66%. Before the volume bound existed the same sweep
produced +2,005% and +146,402% — the concentration was being manufactured by modelled depth, not by
the strategies. Caps are an option (`maxNotionalPerMarketPct`), off by default, because the brief is
highest-return-only.
